## T8 — Halt on a second blocked iteration of a task whose inputs have not changed

- **Outcome:** done (review: PASS)
- **Summary:** The driver now halts the run when a task's second consecutive blocked outcome carries no change (outside .loop/state/) since its first blocked attempt, surfacing the first diagnosis in the halt warning and the run-end report; a run where something changed between attempts still retries and re-evaluates the rule on the next pair.
- **Files:** .loop/run.sh, .loop/tests/scenarios/42-repeat-blocked-halts.sh, .loop/tests/scenarios/11-stall.sh, README.md, .loop/README.md, .loop/manual.md, docs/briefs/B008-driver-in-python.md, docs/briefs/B20260924-1947-gate-shape-and-driver-honesty.loop-brief.md
- **Notes for next iteration:** Two new per-task fields on state.json's tasks, .blocked_head and .blocked_summary, added and read only by run.sh (not part of the planner's contract, not read by render-plan.sh or runstat): blocked_head is `git rev-parse HEAD` captured right before the iteration's own commit, the moment an outcome is blocked; blocked_summary is that iteration's masked summary. On the NEXT iteration for the same task, if outcome is blocked again, the driver diffs prev blocked_head..current HEAD (both still pre-commit at that point) and drops anything under .loop/state/ -- if what's left is empty, nothing changed since the first attempt, and the run halts (new status repeat_blocked, exit 8) surfacing blocked_summary from the FIRST attempt, not the one just run. If the diff is non-empty, or this is the task's first-ever blocked outcome, the driver just updates blocked_head/blocked_summary and continues -- the pair is re-evaluated fresh next time. On any non-blocked outcome (done/gate_fail/review_fail) both fields are deleted, breaking the chain. Deliberately keyed on the TASK, not on 'the iteration immediately before this one': the brief's own item-7 prose says 'the previous iteration FOR this same task', so a different ready task worked in between does not reset the chain, and the chain also survives a resumed run because it lives in state.json rather than iterations.jsonl (which run.sh truncates every run). This does cost 1-2 extra `git` invocations, but only on the (exceptional) blocked path, never on a normal iteration. Scenario 11-stall.sh had two blocked iterations with literally nothing else in the tree changing, which would now trip this rule before the old stall counter -- gave its stub a per-attempt marker file so something always changes and the scenario keeps exercising the stall halt it exists for, per the acceptance criterion. Exit code 8 and status name 'repeat_blocked' are both new; picked 8 since 0-7 were taken, and documented the new row in .loop/README.md, .loop/manual.md and B008-driver-in-python.md's 'exit codes are the contract, unchanged' list (which needed the addition to stay accurate for whenever that Python-port brief is actually worked).
